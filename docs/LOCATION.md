# 第一版：点击一次，定位一次

## 已准备与尚未启用的部分

- 首页 `⌖` 为“我的位置”；`↺` 为“重置地图”，不再混用。
- 用户主动点击后申请隐私/定位授权，调用一次 `wx.getLocation`，不持续定位、不后台追踪。
- 微信返回 GCJ-02 坐标后，经校准矩阵转换到现有 600×579 底图，蓝点与精度圈随地图同步缩放、平移。
- 获取结果后平滑居中；如果等待期间用户已拖动地图或选择其他地点，不强行抢回视角。
- 处理拒绝授权、系统定位不可用、30 秒超时、精度不足、超出已校准区域、切后台与过期回调。
- 普通用户本次位置仅放在内存，不写入收藏或本地存储、不上传、不分享；离开前台时清除。
- 当前 `location-calibration.json` 的 `enabled` 为 `false`，点击时提示“定位待校准”，不会申请定位或显示虚构蓝点。
- 代码已准备，不代表已取得微信接口权限或通过校内真机验收。

## 微信后台准备

校准配置以 `miniprogram/data/location-calibration.json` 为编辑源。每次更改后运行 `node scripts/sync-calibration.cjs`，生成微信可加载的 `location-calibration.js`，然后重新编译。小程序和浏览器均读取生成的 JS 模块；直接 `require` JSON 会导致微信页面启动失败。默认文件已生成，未修改配置时无需执行。

1. 确认注册主体、服务类目与实际“校园地图查找位置”用途。进入小程序后台的开发管理/接口设置，检查 `wx.getLocation` 是否可申请、是否已开通；以当前账号后台显示的准入要求为准，不假设个人主体一定能通过。
2. 已在 `app.json` 配置 `permission.scope.userLocation` 和 `requiredPrivateInfos: ["getLocation"]`。它们不替代后台接口申请。
3. 在用户隐私保护指引中如实填写精确位置信息的使用用途、触发方式、保存方式。普通地图用户的建议说明：

   > 在你主动点击“我的位置”时获取本次位置信息，用于在校园地图上显示所在位置。位置信息仅在设备上临时处理，不上传至开发者服务器，不用于后台跟踪，离开小程序前台后清除本次显示位置。

4. 本开发包还包含校准采集页面：采集员主动保存的参照点会保留在本机，主动导出时复制到剪贴板。若对外保留该页面，应另外如实披露这一用途；公开生产版建议移除采集页面和注册路由。声明开发者不上传数据不等于微信系统自身不处理定位。
5. 使用真实 AppID 编译，并用手机微信体验。开发者工具模拟位置不能证明户外实际精度；浏览器预览不索取浏览器地理位置，也不会冒充微信定位成功。

参考：[微信官方配置示例](https://github.com/wechat-miniprogram/miniprogram-demo/blob/master/miniprogram/app.json)、[腾讯位置服务小程序示例](https://github.com/TencentLBS/tencentmap-miniprogram-skill/blob/main/quick_start_and_best_practices.md)。

## 校内采集：无需手填经纬度

1. 公开版默认不注册采集页。仅在你的本地采集版本中，将 `pages/calibrate/index` 加入 `app.json` 的 `pages`，并移除 `project.config.json` 中对 `pages/calibrate` 的打包排除项。然后添加编译模式，启动页面设为该路径，用真机调试/预览打开；对外发布前恢复排除配置。先按 ASSETS.md 导入真实且坐标匹配的底图，不能在示例网格上采集。
2. 选至少 **6–10 个校准点**，分布在校园周边与中部；另外选 **至少 3 个不同的独立验证点**，不参与拟合。选能在图上精确辨认的室外桥头、路口，避免楼内、楼宇中心和不确定的入口。
3. 站稳后填写地点名称，选择“校准点”或“独立验证点”，点底图上同一位置，再点“采集我现在的位置”。确认位置后保存。采集精度大于 30 米会拒绝保存；建议尽量采用设备误差 10 米以内的样本。超过两分钟的采样需重采。
4. 如果图上难以准确点选，可先保存，导出后结合 SVG 在电脑上精细修正 x/y；x/y 单位是 600×579 底图像素，不能填百分比。
5. 每个位置采集多次对比；若漂移明显，换开阔时段重采。最终同一位置保留一个可靠样本，不以重复记录凑足点数。
6. 点“导出参照点”，把剪贴板 JSON 保存为本地 `location-samples.private.json`。包含采样位置与时间，勿直接提交公开仓库。

## 生成候选校准配置

无需 npm 安装，在项目目录运行：

```sh
node scripts/calibrate-location.cjs location-samples.private.json location-candidate.private.json
```

脚本以局部米制坐标拟合仿射变换，处理底图旋转、平移、不同方向缩放。独立验证点最大误差超过 20 米或参照点共线时会拒绝生成。20 米是本项目第一版的内部验收门槛，不是手机定位精度承诺。

输出默认仍为 `enabled: false`，不会改动正在使用的配置，也不会覆盖同名文件。覆盖范围使用校准点的凸包，避免向未实测区域外推，可能比校园实际范围小；需根据实地与校界检查是否包含校外区域，并修订 `campusBoundary`（GCJ-02 经纬度按边界顺序填写）。不要把矩形截图范围直接当成校园边界。

若整体拟合通过但某区域仍持续偏移，先排除坐标系混用、采样漂移、图片选点错误，再考虑局部图面变形与分区校准。不要靠放宽误差门槛掩盖问题。

## 真机验收与启用

1. 保留原禁用配置的备份；将候选配置复制为 `miniprogram/data/location-calibration.json`，仅在本地验收版本临时改为 `enabled: true`。
2. 在至少三个未用于拟合的位置（教学区、宿舍区、南侧区域）验证蓝点与实际位置；同时检查校园边缘和校外定位提示。
3. 在 iOS / Android 可用设备上检查授权允许与拒绝、手机定位关闭、室内低精度、重复点击、等待期间拖动、切后台后返回。
4. 验证只有点击时定位；位置不会持续更新；精度圈不会被理解为绝对边界。圈半径包含设备估计误差与校准验证误差，仅作参考。
5. 记录日期、设备、参照点、误差、是否通过；不通过则恢复 `enabled: false`。全部通过且后台权限完备后，才保留启用状态发布。

运行代码测试：

```sh
node tests/logic.cjs
node tests/motion.cjs
node tests/location.cjs
```

自动测试使用合成坐标验证计算与状态变化，不代表已完成 UNNC 现场校准。

## 文件

- `miniprogram/utils/location.js`：坐标转换、精度检查与范围判断。
- `miniprogram/data/location-calibration.json`：禁用状态的待校准配置。
- `miniprogram/pages/calibrate/`：校内采集工具，只存本机，主动导出。
- `scripts/calibrate-location.cjs`：离线拟合和独立验证，无第三方依赖。
- `tests/location.cjs`：定位状态与校准数学验证。
